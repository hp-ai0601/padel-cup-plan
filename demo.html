Matching that is live (AS-IS)

Admin Draw at /admin/draw. Pure engine in lib/matching: four rating quartiles, top vs bottom inside a bucket, geo fail-closed at 100 km. This is PAD-52 / PAD-123 — not Wave Format.

Layer 1 · pure

geo / buckets / pair / preview

No Supabase. Quartile sizes floor((i+1)n/4)-floor(i n/4). Bucket 1 = strongest. No cross-bucket.

Layer 2 · IO

pool + round1

One fetch of activated teams. Preview replaces JSON + version++. Commit materializes matches from snapshot only.

Missing

books_closed

Register/payment can still join between preview and commit. Fingerprint 409s — it does not stop the join. Commit body does not send expectedPreviewVersion from the UI.

Tournament shape

flowchart TB C[Books closed — levels lock] W1[Wave 1 in each AREA — top pot vs bottom pot] R1[Repechage 1 — first loss only — pair by level] S[Wave 1 survivors] W2[Wave 2 enters with survivors] R2[Repechage 2 for first-time losers] KO[Knockout sized once so each round halves to Q public] PR[Pro Round of 64 = Q public + P pros] F[Live London Finals 32] C --> W1 --> R1 --> S --> W2 --> R2 --> KO --> PR --> F

Rules that stay fair

  • One Repechage per team. Second loss is out. Every team gets at least two matches.
  • Round 1 pots are per area, not four UK-wide quartiles. Area is not in the schema yet — needs a client lock (club cluster / postcode / radius).
  • Wave 2 drawn against Wave 1 survivors; strongest Wave 2 kept apart.
  • Byes to highest-ranked. Knockout draw size set once after Wave 2.
  • Pro squad size P = 8 / 16 / 32 (HTML default 16). Q public qualifiers = 64 − P.
